# Архитектура и границы стенда

1. Клиент подключается к единому loopback endpoint диспетчера `127.0.0.1:3389`.
2. Первичное RDP-соединение идёт в KRdp greeter на `127.0.0.1:3390`.
   TLS заканчивается в KRdp, диспетчер не расшифровывает сеанс.
3. Пользователь проходит PAM-аутентификацию через Plasma Login Manager.
4. Root-hook запрашивает у диспетчера одноразовый маршрут. Управляющий Unix-сокет
   закрыт правами, UID проверяется через SO_PEERCRED; маршрут живёт 30 секунд.
5. KRdp передаёт клиенту RDP redirection с routing cookie. При новом соединении
   диспетчер одноразово потребляет маршрут и направляет поток в KRdp пользователя.
6. `native-a` использует backend 3391, `native-b` — 3392. Каждый KWin работает
   с собственным виртуальным экраном и пользовательским PipeWire.
7. Обрыв транспорта завершает RDP-подключение, оставляя сеанс Wayland и приложения.
   Новый успешный PAM-вход возвращает пользователя к этому сеансу.

При запуске каждого пользовательского RDP-соединения согласованный начальный
размер клиента применяется к виртуальному KWin через KScreen; после этого
Display Control обрабатывает изменения размеров окна. Изменение режима
пересоздаёт источник захвата/графическую поверхность. Для нового Progressive
surface передаётся полный первый кадр; кадры старого источника отбрасываются.

При новом соединении выделенный `Virtual-0` также включается через KScreen
DPMS: сохранённый headless-сеанс мог погасить его во время отсутствия клиента.
Запрос ограничен единственным виртуальным экраном в режиме терминального
сервера; блокировка и штатная политика бездействия сохраняются.

Guacamole необязателен. Его отдельная проблема находилась после RDP-декодирования:
замена внешнего GDI-буфера не полностью инвалидировала изображение для браузера.
Патч `display-layer.c` помечает заменённый буфер целиком. Для лабораторной проверки
это же поведение реализовано отдельным LD_PRELOAD adapter через публичные API.

## Ограничения

- Один общий greeter допускает последовательные входы; два уже вошедших
  пользовательских сеанса работают одновременно.
- Два заданных пользователя и фиксированное сопоставление backend-портов.
- Общий лабораторный NLA/transport-secret и сертификат: это не персональные
  транспортные учётные данные для многопользовательской эксплуатации.
- Пароль передаётся CLI-параметром KRdp. Не рассматривайте это как готовую
  модель изоляции секретов между недоверенными пользователями.
- Для backend-портов требуется root-only nftables-правило из `runtime/`.
- Проверен доступ через туннель; публикация RDP/guacd-портов в LAN/Internet
  этим экспериментом не предусмотрена.
- Установка меняет менеджер входа, выключает autologin и блокировку экрана
  тестовых пользователей, настраивает виртуальные KWin и перезапускает greeter.
- Персональные transport credentials, передача сокетов с проверкой UID,
  конкурентные greeter, управление произвольными пользователями и production
  hardening остаются задачами дальнейшей разработки.
