# Windows App для macOS: перенаправление и динамическое разрешение

В лабораторном прототипе Windows App сначала подключается к Plasma Login Manager,
а после личного PAM-входа получает RDP Server Redirection с одноразовым маршрутом
к отдельному KRdp пользователя. Адрес и внешний порт остаются общими.

## Проверка `use redirection server name`

По предложению Владимира Гурьева проверен вариант совместимости,
применяемый им с GNOME Remote Desktop:

```text
use redirection server name:i:1
```

Microsoft перечисляет параметр в [официальном описании RDP URI](https://learn.microsoft.com/en-us/windows-server/remote/remote-desktop-services/remote-desktop-uri).
Его наличие не означает исправление любой ошибки handover, TLS или захвата экрана.
Наш текущий пакет redirection передаёт `LoadBalanceInfo`, без имени сервера.

В Windows App:

1. Отключить клиентский сеанс, сохранив приложения на сервере.
2. Открыть контекстное меню **конкретного тестового профиля** → Export → Browse.
3. Сохранить исходный `.rdp` как резервную копию. В его копии заменить ровно
   `use redirection server name:i:0` на `use redirection server name:i:1`.
   Сохранить отдельное имя, например `Distro Matrix A Redirect1.rdp`.
4. Connections → Import from RDP file → выбрать изменённую копию.
   Проверить общий адрес, отсутствие неожиданного Gateway и настройки Display.
5. Повторно экспортировать **импортированный** профиль и прочитать фактический
   файл: строка должна оставаться `:1`. Windows App может добавить суффикс ` 1`
   к имени повторного экспорта, не перезаписывая существующий файл.
6. Проверить личный вход, возврат к несохранённому Kate, ввод, движение картинки
   и реальное разрешение Plasma. Повторить с исходным профилем на той же сборке.

Пароли в экспорт Windows App не входят. Не следует добавлять их в `.rdp`,
публиковать пользовательские профили или сохранять пароль ради теста.
Исходный профиль и подключения к другим системам при нашей проверке не изменялись.

## Что действительно проверено

На ALT Starter Kit p11 ARM64 / UTM, исходники `3bff759`, после исправления
зависимостей KDE integration и доступа к VGEM:

| Проверка одного пользователя | Флаг 0 | Флаг 1 |
| --- | --- | --- |
| Вход через PLM в личный KRdp | Прошёл | Прошёл |
| Возврат прежних Kate/KWin/KRdp | Прошёл | Прошёл |
| Половина экрана, KWin `960×1018` | Прошёл | Прошёл |
| Полный экран, KWin `1920×1080` | Прошёл | Прошёл |
| Новый текст Kate виден после изменения размера | Да | Да |

Это короткие последовательные проверки одного сеанса, без статистического
сравнения частоты сбоев. Флаг `1` принят приложением, но его обязательность
для этого стенда **не установлена**. Первоначальные неверные пропорции широкого
окна до resize не считаются исправленными этим флагом. Два одновременных сеанса
и длительный тест Starter Kit ещё не завершены.

[Доказательства](evidence/alt-starter-p11-arm64/redirection-properties.txt),
[фактическая геометрия и PID](evidence/alt-starter-p11-arm64/redirection-comparison.txt),
[пакеты и особенности ALT](ALT.md).

В Display включено **Update the session resolution on resize**, Retina и
использование всех мониторов выключены. Фактические режимы KWin сверялись
через `org.kde.KWin /KWin supportInformation`; масштабирование картинки клиента
само по себе не считалось изменением разрешения Plasma.
