# ALT Workstation K: остановка изображения при смене разрешения

Диагностика 21 ноября 2026 года, отдельная x86_64 ВМ PVE, официальный ISO
Workstation K 11.4 и зависимости p11: KWin/PLM 6.7.5, Qt 6.11.2,
FreeRDP 3.32.2, Mesa 26.1.8, ядро 6.12.85-6.12-alt1.
`/etc/altlinux-release` в повторном прогоне остался 11.4; это частичное
обновление зависимостей p11, не полное обновление системы и не неизменённый
ISO. Транзакция: 303 обновления, 195 новых пакетов, замена ABI
`libprocesscore10` → `libprocesscore11`; сохранены только установленные
метапакеты KDE. Прототип основан на KDE 6.7.4.

## Две воспроизведённые причины

### Ошибка выделения графического буфера

До исправления `kwin_wayland --virtual` выбрал VirtIO `/dev/dri/renderD128`
с llvmpipe. Открытие узла и наличие OpenGL не гарантировали рабочую
отрисовку: журнал KWin повторял `DRM_IOCTL_MODE_CREATE_DUMB failed:
Permission denied`, `Rendering a layer failed!`. После уменьшения окна
до 960×1018 KRdp получил один ключевой кадр, а затем пакеты прекратились.
При этом счётчик в Konsole продолжал работать, что проверено через D-Bus.

Проверка тем же непривилегированным пользователем: `CREATE_DUMB` на
VirtIO render-node вернул errno 13; на первичном узле VGEM создал буфер
320×240, 307200 байт. В [KWin 6.7.5](https://github.com/KDE/kwin/blob/v6.7.5/src/backends/virtual/virtual_backend.cpp)
выбор первичного узла VGEM предусмотрен именно для таких буферов.

Использованы модуль VGEM и существующее узкое правило
[`99-plasma-rdp-vgem.rules`](../runtime/altlinux/99-plasma-rdp-vgem.rules).
Права физических GPU не менялись. После перезагрузки проверены родитель
`MODALIAS=platform:vgem`, ACL, фактические открытые KWin дескрипторы и
продолжение кадров после смены режима.

### Потерянное уведомление при остановке кодировщика

После устранения ошибки KWin второй сеанс завис при начальной смене режима.
Стек основного потока KRdp: `VideoStream::setActiveEncodingMode` →
деструктор `PipeWireBaseEncodedStream` → `QThread::wait`.
Поток `PipeWireProduce::destroy` находился в `std::thread::join`, а
его рабочий поток — в безусловном `condition_variable::wait`.

Прежний код проверял атомарный флаг перед ожиданием, затем ожидал без
предиката. Команда остановки меняла флаг и уведомляла без того же mutex.
Уведомление между проверкой и ожиданием терялось. Дополнительно рабочий
поток при старте сам устанавливал флаг в `true`, что могло отменить раннюю
остановку. Уведомления о новых кадрах имели ту же проблему.

[`kpipewire-6.7.4-producer-wakeup.patch`](../patches/kpipewire-6.7.4-producer-wakeup.patch)
вводит состояние ожидающей работы и необратимой остановки под одним mutex.
Оба потока ждут с предикатом, поэтому ранние уведомления сохраняются,
а остановка не может быть отменена стартом потока. Здесь нет таймера,
перезапуска сессии или неограниченного накопления кадров.

Диагностика ожидания RDP ACK не подтвердила гипотезу о
`SUSPEND_FRAME_ACKNOWLEDGEMENT`; обработка ACK этим исправлением не меняется.

## Воспроизведение и проверки

Сборка — по [инструкции ALT Workstation K](ALT-WORKSTATION-K.md), из новой
директории подготовленных исходников. `scripts/prepare.py` включает новый
патч KPipeWire. После пересборки следует обновлять библиотеки обоих
вариантов runtime и перезапускать использующие их процессы KRdp.
Замена файла на диске сама по себе не обновляет уже загруженную библиотеку.

`scripts/check-regressions.sh` запускает четыре проверки, включая
[`producer-wakeup.cpp`](../tests/producer-wakeup.cpp): работа до начала
ожидания, остановка до старта, поздняя работа после остановки и 1000
завершений двух рабочих потоков. Проверяется тот же класс, который
использует KPipeWire; зависание ограничено watchdog проверки.
Все четыре проверки прошли в ALT x86_64; проверка синхронизации также прошла
локально на macOS.

Для проверки выбранного DRM-узла от имени пользователя сеанса:

```sh
python3 tests/drm-dumb-buffer.py /dev/dri/card0
```

Номер узла берётся из фактических дескрипторов KWin и `/sys/class/drm`,
а не копируется из этого примера. Проверка выделяет небольшой буфер и
освобождает его закрытием дескриптора.

## Повторная проверка Windows App

Windows App на macOS, два профиля через один frontend RDP:3389, два разных
пользователя, динамическое разрешение включено. Клиентские имена
`127.0.0.1` и `localhost` указывают на один тестовый SSH-forward.
Штатные PAM-файлы ALT совпали с исходными контрольными суммами.

| Проверка | Наблюдение |
| --- | --- |
| Перезагрузка без автологина | Только greeter; оба личных сеанса созданы после входа через PLM |
| Два одновременных пользователя | Отдельные KWin, KRdp, Kate и Konsole |
| Два аварийных обрыва | Принудительно остановлен только SSH-forward; оба клиента показали разрыв |
| Возврат после каждого обрыва | Прежние PID Kate/KWin/KRdp; несохранённые документы сохранились |
| Размер окна / полный экран | Фактические режимы KWin 960×600, 960×1018 и 1920×1080 |
| Изображение после resize | Счётчик и подтверждения кадров продолжаются больше минуты после изменения размера; повторено после второго возврата |
| Ошибки KWin после VGEM | Ни одного `CREATE_DUMB failed` / `Rendering a layer failed` за исправленный прогон |

PID A: Kate 2553, KWin 1958, KRdp 21058; B: Kate 7516, KWin 5755,
KRdp 21092. В A исходный несохранённый маркер `vga00001` дополнен `2` и `3`
после возвратов. В B `vgb00001` дополнен `2` после первого возврата и
сохранён после второго. Финальная проверка счётчиков — 18:29 UTC.

В ходе диагностики перезагрузка с добавлением VGEM завершила исходные
сеансы. Документы для повторной приёмки созданы после этой перезагрузки;
между двумя контрольными обрывами сессии не перезапускались.
Перезапуск Windows App использовался после его диалогов разрыва из-за
тайм-аута инструмента управления окнами Mac. Это не перезапуск Plasma.

Выбранные журналы, стек зависания, проверка буфера, регрессии и финальный
снимок B находятся в [каталоге доказательств](evidence/alt-workstation-k-resize/).

## Память: 900 секунд и 120 секунд покоя

Сбор `/proc` начат с двумя подключёнными клиентами и работающими счётчиками.
В эти 900 секунд входят два обрыва и время повторных входов; это не
900 секунд непрерывной передачи в обоих клиентах. Затем клиенты отключены,
остановлены только тестовые счётчики, выполнен отдельный 120-секундный замер.
Kate и KWin до конца замера оставались прежними.

| PSS, КиБ | A | B |
| --- | ---: | ---: |
| Отключённое состояние после первого обрыва, t=234,64 с | 58635 | 57518 |
| Пик за 900 с | 173401 | 164021 |
| Последний активный замер | 128844 | 119368 |
| После завершения и 120 с покоя | 56013 | 57019 |

Финально у каждого KRdp 4 потока, 21 FD, swap 0. На двух повторных циклах
не обнаружено накопления остаточной PSS; это ограниченный прогон, не
часовой тест и не доказательство отсутствия всех утечек.
Исходные CSV и сводка опубликованы рядом с журналами.
